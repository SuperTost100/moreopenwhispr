Product constraints and screen changes

The screenshots are useful because Flow repeats the same navigation, row, list, and empty-state patterns. The redesign should borrow those patterns without importing Flow's account model or its promotional UI.

  • Keep the provider choices.Antigravity is the recommended setup. Local, BYOK, enterprise, and self-hosted routes remain available when policy allows them.
  • Keep the fork account-free.Do not add OpenWhispr Cloud, plans, billing, teams, workspaces, referrals, usage limits, or upgrade prompts.
  • Keep existing behavior.Do not rewrite IPC, recording, note persistence, policy checks, downloads, or onboarding routes during the visual work.
  • Keep the desktop constraints.Respect the 1200×800 control panel, compact onboarding window, native traffic lights, drag regions, overlays, and content protection.

Routing and visual decisions

The app should use plain labels for processing location. Color can help people scan the route, but it cannot carry the meaning by itself.

Route labels

  • On this deviceMicrophone capture, local model work, storage, and paste.
  • Audio leaves deviceAntigravity transcription through the local agy OAuth session.
  • Uses your API keyBYOK requests. The named provider's billing and terms apply.
  • Custom routeEnterprise, LAN, and self-hosted endpoints. Show the endpoint name.

Keep Noto Sans for the first implementation. The app already bundles it and it covers every supported language.

Use an 8px spacing base, 10 to 12px component radii, 44px controls, visible focus, and complete light and dark color mappings.

Animate only state changes. The route may update once when the user changes provider. Nothing should pulse while idle.

Rollout, checks, and open decisions

Use the branch as the rollback point. Keep each phase small enough to compare against the current app before moving to the next screen.

  1. Resolve fork identity

    Use MoreOpenWhisperer consistently across the current build and fork docs. Check bundle ID, signing identity, publisher, release target, docs URL, and no-endorsement copy.mowProfile.ts, electron-builder.json, .fork/COMPLIANCE.md

  2. Set shared CSS variables

    Add the colors, spacing, radii, focus style, row height, and dark mappings to the existing Tailwind v4 variables. Consolidate duplicate setting-row components.src/index.css, ui/SettingsSection.tsx, ui/button.tsx, ui/card.tsx

  3. Update the control panel

    Keep activeView, lazy imports, policy filtering, and collapse behavior. Change the sidebar and Dictation history first. Add the processing route with a pure view model.ControlPanel.tsx, ControlPanelSidebar.tsx, HistoryView.tsx

  4. Move Settings into the control panel

    Keep every legacy section and subtab alias. Reuse the current SettingsPage logic and replace only its outer layout and repeated rows.SettingsModal.tsx, SettingsPage.tsx, settings/*

  5. Update the remaining screens

    Work through Integrations, Dictionary, Upload, Assistant, and then the Notes components. Do not move feature state while changing layout.IntegrationsView.tsx, UploadAudioView.tsx, notes/*, chat/*

  6. Update onboarding and small windows

    Reuse the established controls and colors. Keep the route machine, drag regions, window sizing, and content protection unchanged.OnboardingShell.tsx, OnboardingFlow.tsx, App.jsx, dictation/*

  7. Run release checks

    Test keyboard use, long translations, reduced motion, every provider route, window sizes, and packaged Electron builds. Remove temporary migration code before merge.locales/*, test/components/*, test/helpers/*

Release checklist

  • Local, Antigravity, BYOK, enterprise, and self-hosted routes still work when eligible.
  • No account, plan, workspace, referral, or upgrade control appears in the accessibility tree.
  • Missing agy, expired OAuth, quota errors, provider errors, and fallback states tell the user what to do.
  • Settings shortcuts, IPC links, and old section IDs still open the correct section.
  • Notes, meeting recording, Assistant, Dictionary, Upload, Integrations, CLI, and onboarding pass their current smoke flows.
  • The control panel works at 1200×800 and below the 800px sidebar breakpoint.
  • Compact and expanded onboarding windows do not clip content.
  • Keyboard order, focus, contrast, labels, and reduced motion meet the current accessibility requirements.
  • Every new app string has a key in all supported locale files.
  • Tests, typecheck, i18n checks, formatting, and the renderer build pass on Node 24.
  • Settings, Notes, Assistant, and Upload remain lazy-loaded.
  • The redesign adds no runtime dependency unless a measured need justifies it.
